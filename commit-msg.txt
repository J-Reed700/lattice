feat(vault): markdown portability — write-through, backfill, settings UI

Adds the Obsidian-crowd unlock from the 60-day plan: notes mirror to
plain markdown files on disk so users can manage them with their own
tools (Obsidian, ripgrep, git, iCloud). SQLite stays the index/query
layer; the vault folder is the portability layer.

Backend (off-by-default, opt-in via Vault settings tab):

- New SettingsCategory::Vault with VaultSettingsDto { vault_path,
  enabled, watch_external_changes }. Default vault_path is empty
  meaning "use ~/Lattice", resolved at write time.

- New features/vault/writeback module:
  - spawn_sync_workspace_note: fire-and-forget per-write hook, called
    after every successful workspace/daily note SQL commit. Reads
    settings, short-circuits if disabled, writes <vault>/notes/<id>.md
    atomically via temp file + rename so an external watcher never
    sees a half-written file.
  - YAML frontmatter is Obsidian-compatible, with quote-escaping in
    title and tags (handles backslash + double-quote).
  - spawn_backfill: one-shot walk of every workspace note when the
    user flips vault.enabled false -> true. Logs per-note failures
    but never aborts the walk; one bad row never blocks the rest.
  - 6 unit tests covering frontmatter, escaping, default resolution,
    atomic write.

- Wired into create_workspace_note_impl, update_workspace_note_impl,
  update_daily_note_content_impl. Daily and workspace notes share the
  daily_notes_workspace table backend-side, so both go through the
  same writeback path -- no separate daily/ subdirectory.

- SettingsTransitionHints { vault_just_enabled } added to the
  SettingsSideEffectsPort. UpdateSettingsUseCase now captures
  previous state and computes the hint; the side-effect impl reacts
  by spawning backfill -- so a side-effect impl never has to read
  before/after settings itself. Reset use case passes default hints.

- ContainerSettingsSideEffects gains a db_pool field for the backfill
  walk. Reuses the same SqlitePool the rest of Container shares.

- Path validation: vault_path goes through the same
  InputValidator::validate_directory_path the indexed_paths payloads
  use. Empty string is the sentinel for "use default" and skips
  validation. The Vault arm of validate_security_constraints in
  UpdateSettingsUseCase runs before any merge lands so a hostile
  payload never makes it onto disk.

Frontend:

- VaultSettings interface in types/api/settings.ts mirroring the
  Rust DTO (camelCase per existing convention).

- VaultTab.tsx: folder picker (Tauri open-dialog), enable toggle,
  watch-external toggle (disabled placeholder for v1.1 watcher work),
  "Reset to default" affordance when a custom path is set, footnote
  explaining the atomic-write + Obsidian-compatible frontmatter.

- Registered in Settings.tsx as a new General-group tab between
  Indexing and Display, exported from the settings index barrel.

Intentionally NOT in this commit (v1.1):

- Filesystem watcher (reverse direction: re-import external .md
  edits back into SQLite). The Vault tab toggle is wired but
  disabled with a copy note explaining it lands later.

- Conflict resolution UI for when external edits diverge from SQLite
  state -- needs the watcher first.

Verified: cargo check --lib clean, cargo test --no-run clean
(6 new vault tests compile alongside settings tests), npm run
type-check shows zero new errors (one pre-existing vaultApiMock
mock-infra error untouched).
