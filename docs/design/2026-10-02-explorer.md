# Explorer: a folder beside a chat

2026-10-02. Replaces the Study (flashcards) rail item.

## What it is

A split view: on the left, a folder from disk, browsed the way VS Code's explorer
browses it (tree + read-only file view). On the right, the normal Lattice chat:
same pipeline, same turn record, same web and library tools. The chat can read
the folder, and when it talks about code it points at the lines, which light up
in the viewer.

```
┌ rail ┬──────────── left: the folder ────────────┬──── right: chat ────┐
│      │ lattice  ~/Code/lattice     [Close folder]│ thread switcher  +  │
│      ├──────────────┬────────────────────────────┤                     │
│      │ tree         │ src/foo.rs                 │  ChatPanel          │
│      │  ▸ src       │  10 │ fn main() {          │  (unchanged         │
│      │  ▸ docs      │▌ 11 │   …  ← highlighted   │   pipeline)         │
│      │    README.md │  12 │ }                    │                     │
└──────┴──────────────┴────────────────────────────┴─────────────────────┘
```

## Decisions

- **Name: Explorer**, route `/explorer`, rail slot ⌘6 (where Study was),
  `FolderTree` icon. `/compare` (the document comparison table) is a different
  thing and stays as it is.
- **Study leaves the rail; its flashcards move into Learning Studio.** The
  decks become a "Flashcards" section on the Studio landing page under
  Programs (`src/components/LearningStudio/flashcards/`), reviewed in place via
  `/studio?deck=<id>`. The `/study` route and rail item go; "study deck from
  conversation" now opens `/studio?deck=<id>`. The Rust `features/study` module
  and its commands stay as they are: Studio's per-program Recall tab already
  calls `review_study_card` / `update_study_card`, and `list_study_decks`
  returns program decks too, so the section and the Recall tab show the same
  cards with the same review state.
- **The folder is read live, not indexed.** The model gets `list_directory`,
  `read_file`, `search_files` and `find_files`, confined to the scope. "The
  vector database" means the existing library: `semantic_search` and the KB
  and web toggles work exactly as they do in Chat. Indexing a folder into the
  library is a possible later step, not this one.
- **Highlights come from line references in the answer, not a tool call.** The
  model writes `` `src/foo.rs:10-24` `` (inline code, path relative to the
  scope root, 1-based inclusive lines, or `path:12` for one line). The answer
  renders each one as a chip; clicking it opens the file and highlights the
  range, and while the answer streams the newest reference is revealed
  automatically. Why not a `highlight` tool: a tool call costs a full model
  round (minutes on a local model), fails on models without tool calling, and
  needs its own persistence. A reference in the text costs nothing, works on
  every model, and is saved with the message.
- **The open file and selection ride along with each turn.** The model always
  sees which file is open and the selected lines, with their text, in the prompt.
  A model without tool calling can still answer about what is on screen.
- **The folder is locked once picked.** Before a folder is open the page is a
  start screen: one large "Choose a folder…" button (the system folder picker)
  and "Your folders", every folder picked before (a managed list in
  `lattice.db`; see the folder-index doc). Once a folder is open, nothing in the view
  moves the scope: no breadcrumb to widen it, no "set as scope" to narrow it,
  no picker in the bar. Expanding folders in the tree is browsing inside the
  scope. The only way out is "Close folder", back to the start screen. Each
  scope is a deliberate choice, so later per-folder state (threads now, an
  index later) exists only for folders the user chose, not every folder they
  passed through.
- **Explorer threads are conversations** with `conversations.explorer_root` set.
  They live in Explorer's thread switcher (filtered to the current root) and
  are left out of Chat's sidebar, so a thread is never continued without its
  folder.

## Contracts (backend ↔ frontend)

All DTOs are specta types, camelCase on the wire. Paths inside a scope are
relative, `/`-separated, no leading `./`; `""` is the root itself. Roots on the
wire are canonical absolute paths.

```rust
// features/explorer/dto.rs
ExplorerRootDto        { root: String, name: String }
ExplorerEntryDto       { name: String, path: String, kind: ExplorerEntryKind, size: Option<u64>, ignored: bool }
enum ExplorerEntryKind { Directory, File }            // "directory" | "file"
ExplorerListingDto     { root: String, path: String, entries: Vec<ExplorerEntryDto> }  // dirs first, then files, case-insensitive
ExplorerFileDto        { root: String, path: String, text: Option<String>, lineCount: u32,
                         sizeBytes: u64, language: Option<String>, binary: bool, tooLarge: bool }
ExplorerSearchMatchDto { path: String, line: u32, column: u32, preview: String }
ExplorerSearchResultDto{ matches: Vec<ExplorerSearchMatchDto>, truncated: bool, filesScanned: u32 }
ExplorerLineRangeDto   { startLine: u32, endLine: u32 }                 // 1-based, inclusive
ExplorerFocusDto       { openPath: Option<String>, selection: Option<ExplorerLineRangeDto> }
```

Commands (features/explorer/plugin.rs):

| command | args | returns |
|---|---|---|
| `explorer_resolve_root` | `path` | `ExplorerRootDto` (canonicalised; must be an existing directory) |
| `explorer_list_dir` | `root, path` | `ExplorerListingDto` |
| `explorer_read_file` | `root, path` | `ExplorerFileDto` (text capped at 2 MiB; over that `tooLarge`, `text: null`) |
| `explorer_search` | `root, query, regex, pathPrefix?, maxResults?` | `ExplorerSearchResultDto` |
| `set_conversation_explorer_root` | `conversationId, root?` | `()` (stores canonical root; `null` clears) |

The folder index and folders-list commands (`explorer_index_*`,
`explorer_folders_list`, `explorer_folder_*`) are in
`2026-10-02-folder-index.md`.

Changed existing types:
- `ConversationDto.explorerRoot: Option<String>`.
- `ToolPreferences.explorerFocus: Option<ExplorerFocusDto>`. Validated against
  the conversation's stored root; ignored when the conversation has none.

Migrations: `src-tauri/migrations/20261002100000_conversation_explorer_root.sql`,
`ALTER TABLE conversations ADD COLUMN explorer_root TEXT;` plus an index; and
`20261002110000_explorer_folders.sql`, the folders list. Never touch the
squashed init file.

Line-reference grammar (backend prompt and frontend parser must agree):
inline code whose whole content matches
`^([A-Za-z0-9_@.+\-/]+):(\d+)(?:[-–](\d+))?$`, where the path has at least one
`/` or `.`. Anything else in backticks is ordinary code.

## Scope safety (backend)

- Every path is resolved under the canonical root and re-canonicalised; anything
  that lands outside (`..`, absolute paths, symlinks pointing out) is refused.
- Walking honours `.gitignore` and always skips `.git`. Listing shows ignored
  entries with `ignored: true` (the tree dims them); search and `find_files`
  skip them.
- Read-only. Nothing in this feature writes to the folder.
- Search is bounded: max files scanned, max bytes per file, binary files
  skipped, a wall-clock cap; `truncated` says when a bound was hit.

## Model tools (backend)

Offered only on turns of a conversation with `explorer_root`, only when the
model supports tool calling, never on closed-book turns. Dispatched in
`chat/tool_loop.rs` beside the history tools.

- `list_directory { path? }`: one level, dirs first, ignored entries left out.
- `read_file { path, start_line?, end_line? }`: numbered lines (`  12│ text`),
  at most ~400 lines per call; the result says how to read the next window.
- `search_files { query, regex?, path? }`: matches with `path:line` and a
  preview, capped (~50).
- `find_files { pattern }`: paths whose name or relative path matches a
  substring or glob, capped.

Each call is a turn step with a plain label (`Read src/foo.rs 1–400`,
`Searched for "fn main"`).

## Prompt (backend)

An explorer turn's system context gains one block: the scope's name and a
short top-level listing; the open file's path and the text of the selection
(or the first window of the file when nothing is selected), capped against the
context budget; and the citation rule above, stated once, with an example. The
library and the web are described as outside knowledge; the folder is what the
user is looking at.

Grounding verification checks claims against retrieved sources. Sentences that
carry a line reference are about the folder, not those sources, so they are
not judged against them.

## Frontend

- `src/components/Explorer/`: `ExplorerPage`; its start screen
  `ExplorerStart` (native folder picker via `@tauri-apps/plugin-dialog`
  `open({ directory: true })`, starting at the most recent folder still on
  disk, and the "Your folders" module in `ExplorerFolders` /
  `useExplorerFolders`); scope bar (folder name, full path, index pill,
  "Close folder", which reads "Closing…" while the index lets go); lazy tree
  (keyboard navigable, ignored entries dimmed, no scope controls), `CodeViewer` (CodeMirror 6, read-only,
  language by extension, line numbers, gutter selection, highlight
  decorations with scroll-into-view). A folder opened from the list keeps
  the name it was given there.
- `src/stores/explorerStore.ts`: root, expanded dirs, open file, selection,
  active highlight, conversation per root (forgotten when a folder is
  removed with its threads). No folder list: that is the backend's.
- Right pane mounts the existing `ChatPanel`; Explorer makes its thread the
  active conversation. A selection shows as a removable chip above the composer
  ("lines 10–24 · foo.rs"). Each send carries `explorerFocus`. While the
  folder's index is scanning or indexing, one quiet line above the composer
  says how far along it is (`ExplorerIndexNotice`).
- `TiptapEditor/extensions/codeRefMarks.ts`: decorates line references as
  chips, like `citationMarks`; `Message.tsx` routes chip clicks to the
  explorer store. Active only in explorer conversations.
- Chat's sidebar leaves explorer threads out, and Chat never opens to one.
