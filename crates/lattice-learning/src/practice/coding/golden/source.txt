--- user ---
Write one easy python problem. The learner writes a single function in solution.py. Programs run on a fake Python.

It practises the lesson "Lookups", whose objective is: Use a table to avoid repeated scans.

The problem must call for these patterns:
Hash map lookup: Something is asked again and again about values already seen, and remembering them by key answers it at once.

The problem may also call for other patterns, each named by the handle written before it:
[t1] Frequency counting: The answer depends on how many times each value occurs, not on where it occurs.
[t2] Prefix sums: Many questions about the total of a stretch of values, each of which one running total settles.
[t3] Two pointers: Two positions move through the input by a rule, and each move rules out part of it.
[t4] Sliding window: The answer is about a contiguous stretch that grows at one end and shrinks at the other.
[t5] Fast and slow pointers: A walk through linked or repeating data where two walkers at different speeds meet or part.
[t6] Monotonic stack: Each element wants the nearest earlier or later element that is larger or smaller than it.
[t7] Sort first: The input has no useful order, but once it has one, the answer is found in a single pass.
[t8] Interval merging: Ranges overlap or touch, and ordering them by start makes the overlaps adjacent.
[t9] Heap selection: Only the best few of a stream matter, and the next best must be available as items come and go.
[t10] Bucket counting: The values fall in a small known range, so counting them in slots orders them without comparing.
[t11] Trie: Many strings share beginnings, and queries are about prefixes.
[t12] Union find: Items are joined into groups as the input goes on, and the question is whether two are in one group.
[t13] Tree traversal: The answer is gathered by visiting every node of a hierarchy, with each node's answer built from its children's.
[t14] Graph traversal: Items are linked, and the question is what can be reached from where, or by how few steps.
[t15] Binary search: The input is ordered, or the answer is on one side of a line that a single check can find.
[t16] Binary search on the answer: The answer is a number, and for any guess it is cheap to tell whether the guess is too small or too large.
[t17] Backtracking: Every way of making a series of choices must be tried, and a bad partial choice can be abandoned early.
[t18] Greedy choice: At each step one choice is never worse than the others, so it can be made and never revisited.
[t19] Dynamic programming: The same smaller questions come up again and again, and each answer is built from answers to those.
[t20] Divide and conquer: The input splits into independent parts that are solved alike and then combined.
[t21] Bit manipulation: The values are small sets or flags, and operating on their bits does what a loop over members would.

Rules:
- The title and statement must never name a pattern or technique that solves the problem, or hint at one by name. The learner recognises the pattern.
- Arguments and expected results are Python literals, one argument for each parameter in the signature's order. Use built-in types and annotations such as list[int]; import nothing.
- The reference is a complete, correct solution.py that meets the target complexity.
- A misreading is a complete solution.py that a careful learner could write by reading the statement wrongly, or by missing an edge. Write at least three, and make each fail a case you wrote. It must still run.
- Write examples the statement shows, hidden cases that each probe an edge or a misreading, and at least one scale case.
- A scale case gives an argument expression, not a literal, built only from calls of range, list, tuple, dict, set, str, int, len, sum, min, max, sorted, reversed, zip and enumerate, literals, arithmetic, comparisons, conditional expressions, indexing and comprehensions, such as list(range(50000)), [3] * 100000 or [i * 7919 % 100003 for i in range(100000)]. It has no expected result: the reference's answer is recorded. It is compared exactly, so the problem's answer for it must be one deterministic value, such as a number, a string or a sorted list.
- "clarifications" are questions a candidate could ask that the statement leaves open, each with the answer the cases assume.
